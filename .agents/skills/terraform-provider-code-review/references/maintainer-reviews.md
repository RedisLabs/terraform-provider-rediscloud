# How to conduct a provider review

These examples come from public provider reviews, including discussions on PRs authored by the maintainers. Use the reasoning and verify the facts in the current diff. A maintainer's earlier approval applies to the version they reviewed.

| Review move | How to apply it | Public example |
| --- | --- | --- |
| Open with the contract | State what a user could do before the migration. Trace an explicit empty filter through the old lookup and the new one. Ask for the smallest configuration that proves the difference. | [Empty ACL role name](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1177#discussion_r4642581968) |
| Review one stack layer | Ask whether this PR works on its immediate parent. Introduce an extension point with the first consumer that needs it. Keep useful shared behavior when both callers actually need it. | [Stack scope](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1177#pullrequestreview-5992868973) |
| Challenge a passing test | Ask whether the assertion would still pass if the filter were ignored. Seed a second, distinguishable candidate and assert its exclusion. Include both service variants when matching IDs could hide a call to the wrong endpoint. | [Filter counterexample](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1028#discussion_r4318284402), [distinct IDs](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/914#discussion_r4047108807) |
| Test a lifecycle exception | Walk the resource through a transient state. A partial API read during key activation can make unconditional replacement destructive. When removing replacement, verify that Update actually sends the changed field. | [Pending key activation](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1158#discussion_r4626757598), [update contract](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/813#pullrequestreview-4197163361) |
| Follow ownership across resources | Change an unrelated field and inspect the outgoing request. An omitted field managed elsewhere must stay omitted or the update can erase another resource's settings. | [Configuration ownership](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1123#discussion_r4401886178) |
| Revisit an earlier proposal | Check when the remote object actually disappears and what status reaches the user on timeout. If evidence changes the diagnosis, revise the original suggestion in the thread. | [Asynchronous deletion](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1024#discussion_r4413351343), [polling diagnostics](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1020#discussion_r4584519497) |
| Separate blockers from improvements | Explain which issue affects correctness today. Explicitly label an optional simplification. Defer a larger refactor when independent delivery is safe. A code approval can still identify an outstanding CI gate. | [Deferred refactor](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/895#discussion_r3552114359), [approval with optional notes](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/770#pullrequestreview-3856010166), [CI caveat](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/808#pullrequestreview-4164492044) |
| Close the loop on evidence | On re-review, identify the fixing commit and assertion, say which part is still open, then narrow the next review to outstanding issues and new changes. If a change breaks compatibility, check that reverting it also fixes tests and release notes. | [Initial review](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1024#pullrequestreview-5672574073), [subsequent approval](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1024#pullrequestreview-5751663740), [compatibility rollback](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/922#discussion_r3720974571) |

For a blocking review, write something an author can verify in one pass. For example, “After Create returns an ID, the final GET can time out. This branch returns before writing state, so the next apply tries to create another object. Please assert the response contains both the ID and the read error when the fake API takes that path.” For an approval, identify the actual before/after behavior, evidence and remaining check, if any. Keep review messages and public documentation free of private references. [Public documentation review](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1123#discussion_r4401403689)

## When the diff touches cleanup, tests or shared infrastructure

- Follow destructive cleanup to its selection predicate. Check that an asynchronous delete has reached the state the next test or API call requires. Check that the sweeper is discovered by the test entry point. [Creation-plan cleanup](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/800#discussion_r3080252692), [sweeper discovery](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1024#discussion_r4392793042)
- Read the test workflow's path filters and prechecks. A green component job may skip shared helpers. Keep test inputs and expectations visible, and explain separate waits when they observe different transitions. [Shared helper CI](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1024#discussion_r4392793052), [separate waits](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1119#discussion_r4442319238)
- Check the client's serialized payload for nil versus explicit empty values. Verify import while the feature under test is present. Append conversion diagnostics so earlier warnings reach the user. [Tag serialization](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/808#discussion_r3131461220), [import fixture](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/808#discussion_r3131515400), [diagnostics](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/743#discussion_r2728490072)
- For new validation, distinguish a permanent configuration invariant from a list of values the service may extend. Check feature requirements against the pinned Terraform version. [API validation](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1024#discussion_r4294958319), [version requirement](https://github.com/RedisLabs/terraform-provider-rediscloud/pull/1024#discussion_r4392793069)
